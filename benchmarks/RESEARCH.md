# Earlier, stable bilingual captions

**Test committing English words that agree across successive Whisper passes, then translating complete phrases.** Users currently wait for a pause or a full audio window before seeing a caption. One paced replay produced its first caption at 7.86 seconds and its last caption 3.82 seconds after recording ended. Earlier partial decoding could reduce that wait, but each additional pass consumes CPU. Measure both the time saved and the extra work. [Local replay](results/live-candidate.json) · [Macháček, Dabre and Bojar, 2023](https://aclanthology.org/2023.ijcnlp-demo.3/)

## What can be cached?

Both Whisper and Marian are encoder–decoder models. In the measured Transformers 4.49.0 setup, Whisper and all three OPUS-MT model configurations enable `use_cache` by default. Each existing `generate()` call can reuse decoder self-attention keys and values for previously generated tokens and cross-attention keys and values for its fixed encoder output. The application caches model weights across requests and starts a new generation for each submitted segment. [Local model calls](../src/speech_translate/models.py) · [Whisper attention](https://github.com/huggingface/transformers/blob/v4.49.0/src/transformers/models/whisper/modeling_whisper.py) · [Marian attention](https://github.com/huggingface/transformers/blob/v4.49.0/src/transformers/models/marian/modeling_marian.py)

Extending the audio window can change earlier encoder representations. Extending the English source phrase can do the same for Marian. Either change invalidates the assumption behind reusing a previous generation's decoder state. Keep committed text and its source time span at the session level. Scope decoder KV state to the exact encoder output, target model and decoding hypothesis. PagedAttention is relevant when concurrent generations compete for GPU KV memory. Its paper measures GPU LLM serving workloads. A single short CPU translation needs its own evidence of memory pressure before adopting that architecture. [Whisper architecture](https://proceedings.mlr.press/v202/radford23a.html) · [Kwon et al., 2023](https://arxiv.org/abs/2309.06180)

### What the cache saves on this CPU

We translated the four human English transcripts from the FLEURS development manifest into Spanish with the application's four-beam OPUS-MT settings. After one warm-up per mode, four passes per mode alternated order. Median generation time for all four sentences was **4.05 s with the KV cache on** and **12.27 s with it off**. Every run produced identical output token IDs. Per-pass times ranged from 3.41 to 5.46 s with caching and 10.01 to 20.58 s without it. This test measures translation generation on an Intel Core i7-9750H using two CPU threads. Speech recognition, tokenization and network time are outside the timer. The shipped model already enables the faster setting. [Measurement script](profile_mt_cache.py) · [Recorded timings and model revision](results/mt-cache-es.json)

After preparing the development manifest with `python benchmarks/prepare_fleurs.py`, run the following from the repository root with the Spanish model cached.

```bash
python benchmarks/profile_mt_cache.py tmp/fleurs-benchmark/manifest.jsonl outputs/mt-cache-es.json --offline
```

## Ranked experiments

1. **Earlier English commits.** Replay the same speech in half-second frames. Compare the current pause policy to decoding the growing buffer every one or two seconds. Commit the longest common word prefix across two consecutive hypotheses, retain the unconfirmed tail, and flush it on stop. Track first *stable* caption, missing or duplicated boundary words, CPU seconds, and final WER. [Whisper-Streaming](https://aclanthology.org/2023.ijcnlp-demo.3/)
2. **Phrase-level translation.** With identical ASR hypotheses, compare translating at every update against translating a stable phrase at punctuation, a pause, or a maximum wait. German word order makes word-by-word target commitments particularly risky. Measure erased target words per final word, final chrF++ per language, and time to a stable translated caption. [Re-translation versus Streaming](https://aclanthology.org/2020.iwslt-1.27/)
3. **Decoder cost.** With fixed audio, source text, weights and thread count, compare default KV caching against `use_cache=False` as a diagnostic control. Record output token IDs, time per generated token, and peak memory for ASR and MT separately. Then score Marian beam widths 1, 2 and 4 against human translations. Profile paged cache allocation if concurrent GPU traces identify allocation or KV memory as the bottleneck. [PagedAttention](https://arxiv.org/abs/2309.06180)
4. **ASR correction from competing hypotheses.** HyPoradise trains language models to correct several candidate transcripts for the same utterance. A generated correction can introduce words absent from every candidate. For a local experiment, retain Whisper’s original transcript and compare its top result, the best available candidate scored against a reference, and an optional model suggestion. Count newly correct and newly incorrect names, numbers and negations separately. Measure added review time and translation quality on held-out audio. Let the listener replay the recording and accept an edit before applying it. [Chen et al., HyPoradise, 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/6492267465a7ac507be1f9fd1174e78d-Abstract-Datasets_and_Benchmarks.html)

5. **Prefix caching in a future local LLM corrector.** As a first trial, give a decoder-only model three numbered Whisper hypotheses and constrain the output to one candidate number, including the original. Put the fixed task instructions first, followed by a session glossary and the changing hypotheses. Cache only tokens that exactly match the prefix of the new request under the same model, adapter, tokenizer and positions. Discard the affected suffix when the glossary or candidates change. Compare identical requests with cold and warm prefixes. Track first-token latency, reused token count, memory and chosen candidate. Test this after the candidate selector earns its place on recognition quality. [Zheng et al., SGLang, 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/724be4472168f31ba1c9ac630f15dec8-Abstract-Conference.html)

Choose settings on development audio. Reserve an unseen evaluation set with long speech, accents, names, numbers, pauses and silence. Alternate run order, repeat on the intended Space hardware, and measure cold starts separately. Report median and p95 browser-visible first and final caption delays, request queue time, streaming real-time factor, strict and Whisper-normalized WER, and per-language chrF++ retention against gold-text MT. Use paired confidence intervals on a sufficiently large held-out set to decide whether any speed gain preserves quality. The existing four-clip test set serves as a regression check.
